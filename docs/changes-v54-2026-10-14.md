# Changes in v54 (2026-10-14), on top of v53

Backend, migrations and UI unchanged.

## Changed
- All 6 send nodes (`Send Reply`, `Send Tutor Reply`, `Send Try Again Notice`, `Send Notice`, `Send Approved Template`, `Send Free Text (inside 24h window)`) are now HTTP Request nodes that POST to `https://graph.facebook.com/v20.0/<phone number id>/messages` with one n8n credential `Meta WhatsApp token (Header Auth)` (Authorization: Bearer ...). This is the integration style the owner's APPU workflow uses, without its hard-coded token. The phone number ID comes from `Resolve Settings`. The WhatsApp-node credential is no longer used. Text is cut at 3800 characters; the template body sends the mission title as variable {{1}}.
- `n8n/gen_sdk.py`, `n8n/gen_merged.py`, `n8n/build_json.cjs`: build the above; `n8n/workflows/whatslearn-all-in-one.json` regenerated (46 nodes).
- `tests/whatsapp-bridge.cjs`: new test (25 total) for the send nodes: Graph URL, Header Auth credential only, no token in the file or URL, text, 3800 limit, template and retry bodies.
- Docs: `docs/whatsapp-n8n-setup-v54.md` (credential steps, one-Meta-callback note), `docs/appu-workflow-review-2026-10-14.md` (read-only review and comparison), this file, `docs/handoff-v54-2026-10-14.md`.

## Not adopted from APPU (on purpose)
No Meta POST without signature, no dedupe-less flow, first-message-only handling, tokens in nodes, hard-coded numbers, AI-side scoring.

# Changes in v52 (2026-10-13), on top of v51

Fixes Meta webhook verification. Backend, migrations and UI unchanged.

## Why verification failed
1. The merged workflow used one Webhook node with the multi-method option (GET and POST). In the owner's n8n it imported showing only POST, so Meta's GET check had no route.
2. The Meta callback URL pointed to `/webhook/...` (production), which exists only while the workflow is active; the workflow is kept inactive.
3. A short verify token would also have been refused: the check requires 16+ characters (`WHATSAPP_VERIFY_TOKEN`).

## Changed
- `n8n/gen_sdk.py`: two Webhook nodes on path `whatslearn-whatsapp`: `Meta Webhook GET (verify)` (GET, no raw body) feeds `Check Verify Token`; `Meta Webhook POST (messages)` (POST, raw body) feeds `Validate Meta Signature`. Removed the `Is Meta Verification?` branch node and the multi-method option.
- `n8n/code/wa-verify-challenge.js`: also accepts nested `hub.*` query keys; token still only from `$env.WHATSAPP_VERIFY_TOKEN`, 16+ characters. Correct token returns the challenge (HTTP 200, plain text via `Answer Challenge`), anything else returns 403 (`Refuse Challenge`).
- `n8n/workflows/whatslearn-all-in-one.json`: regenerated (42 nodes incl. 3 notes, now 4 entry points: 2 webhooks, 2 schedules). No `webhookId` in the file.
- `tests/whatsapp-bridge.cjs`: new test (23 total) for the GET/POST webhook shape, same path, challenge 200 / 403, nested query keys, short token refused, no token in JSON or code.
- Docs: `docs/whatsapp-n8n-setup-v54.md` with the new section "3b. Meta webhook verification"; this file; `docs/handoff-v52-2026-10-13.md`; link names updated in older docs.

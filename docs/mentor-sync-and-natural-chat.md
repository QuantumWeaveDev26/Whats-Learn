# Mentor account sync and natural chat

The linked WhatsApp mentor reads a signed PROFILE response before handling a message. It interprets the meaning of varied requests, then sends bounded commands to the website. Starting/resuming, final submission, course changes and progress use existing server functions. n8n never grades work or awards completion itself. Explicit STOP, account-link proofs and task submissions remain intact.

The website PROFILE response now includes an account-scoped context object: saved name, separate personal setup and journey choices, completed and pending missions across all four courses, reviewed learning skills, points, current draft metadata and reminder settings. It is loaded afresh for each request. Observed practice is not used to infer personality, mood or intelligence. Exact age bands, authentication details and phone numbers are excluded from AI context. One-time personal setup remains locked; journey settings remain editable.

Natural conversation is separated from assessed answers. The classifier can recognize paraphrases and multilingual requests; uncertain messages reach the tutor instead of becoming practical answers. Final saving still requires correct, relevant practical work and the existing server review. Accepted parts persist during a break. A website course change parks the former chat draft without deleting it. Unfinished web and chat drafts remain separate, as previously requested; saved progress is shared.

The teaching contract calls for a named greeting at the start, then direct answers without repeated greetings or name prefixes. Default replies target 20–35 words and one familiar example; detailed steps are available when requested. The formatter keeps complete sentences instead of cutting an answer mid-thought. “I want to learn” explains the current lesson even when a ready draft exists, rather than repeating SAVE/EDIT. It adapts to saved interests and learning style, stays calm under frustration, corrects mistaken prior replies and admits uncertainty. Provider failure can fall through to the n8n tutor with current account facts. A failed shortening call no longer discards a usable answer.

Task resumption and submission, points, progress and roadmap replies now preserve the verified server response instead of asking the tutor to rewrite account state. Journey-location questions include the real `/learn` URL. Learning/explanation requests are a separate intent from returning to work. A filled draft is explicitly pending review, never described as strong or correct. Old assessment text and draft contents are excluded from general tutor context. The tutor memory namespace was changed to v3 to leave earlier invented booking-feedback claims behind; account data and saved drafts were not reset. How-to replies allow up to 80 words and format complete numbered steps on separate lines. Formatting never treats a list number as a sentence or leaves an empty trailing number.

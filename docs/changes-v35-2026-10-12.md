# v35 (12 October 2026): one new mission per India-time day

Built from v34 in a separate working copy. v34 (companion link) already existed and older versions are never overwritten, so this is v35. It contains everything in v34, including the ChatGPT companion link. Nothing was deployed or published; the original ZIP, the source project, the live Site and every database were not touched.

## The rule
A learner can complete **one new scored mission per India-time calendar day (Asia/Kolkata, UTC+5:30), across all four courses**. The day changes at **00:00 IST, which is 18:30 UTC**. This is the same for signed-in learners and guests, wherever they are and whatever their device clock or time zone says. A learner in New York at 8 pm on 12 October (UTC-4) is already in India's 13 October, so their day changes at 2:30 pm New York time.
- Signed in: the server reads its own clock, converts it to the India day (`practiceDay` in `lib/play.ts`) and stores that day in `mission_scores.day`. The database's unique index on (user, day) still blocks a second score. Any time zone, date or score in the request is ignored.
- Guests: the same India day, checked in the browser (`lib/guest-points.ts`). Guest progress is stored only in that browser, so the limit does not follow the learner to another device and may be lost if browser data is cleared. The page says so.
- Revisits are practice and earn no points; a refused second mission saves nothing; nothing is erased when a day is missed.
- Practice days in the rewards card already used India time, so points, practice days and the streak now share one day boundary.

## What changed from v34
- Removed `lib/local-day.ts` (the learner-local-day helper added in v32). Nothing else used it.
- `lib/mission-points.ts`, `lib/guest-points.ts`: use `practiceDay` (India) instead of a browser time zone. `lib/mission-score.ts`: messages say the limit resets at midnight India time, and the guest note adds that data may be lost if browser data is cleared.
- `app/api/work/route.ts`, `lib/learning-service.ts`, `app/learn/page.tsx`: the browser no longer sends a time zone and the points request no longer takes `?tz=`.
- `tests/mission-points.cjs`: the local-day test is replaced by an India-day boundary test (23:59:59 vs 00:00 IST, the next India midnight, learners in New York and Kiritimati sending their own zone, the server ignoring a sent zone, guests on the same boundary, and the guest and daily-limit messages). Notes in `docs/changes-v32-…` and `docs/changes-v33-…` carry a "superseded" line pointing here.

# Changes in v53 (2026-10-13), on top of v52

Adds a path that needs no n8n server access. Backend, migrations and UI unchanged.

## Changed
- `n8n/workflows/whatslearn-all-in-one.json` (46 nodes incl. 4 notes). All four entry points (two webhooks, two schedules) now go through: `My Settings (edit here)` (a Set node with five `PASTE_...` placeholders) -> `Resolve Settings` (Code) -> `Which Part Is Running?` (Switch) -> the existing chat / sync / reminder parts.
- `Resolve Settings` (`n8n/code/wa-resolve-settings.js`): the server environment variable wins when set; otherwise the value typed in the node is used; a value still containing `PASTE` counts as not set. Blocked environment access falls back to the typed value.
- All Code nodes now read their settings from `Resolve Settings`: `wa-verify-challenge.js`, `wa-check-signature.js`, `wa-sign-message.js`, `wa-compose-tutor-reply.js`, `notices-*.js`, `reminders-*.js`. The 6 WhatsApp send nodes take the phone number ID from the same place. Error messages now point at the node.
- `n8n/gen_merged.py`: builds the new structure. `n8n/build_json.cjs`: label v53.
- `tests/whatsapp-bridge.cjs`: harness resolves settings; v52 webhook test adjusted; new test "No server access path" (24 tests total).
- Docs: `docs/whatsapp-n8n-setup-v54.md` (new section "I cannot edit server settings: the short path", settings table, updated env list), this file, `docs/handoff-v53-2026-10-13.md`.

## Still needs server settings
`NODE_FUNCTION_ALLOW_BUILTIN=crypto` (signing and signature checks). Not needed for the Meta verification step. `N8N_BLOCK_ENV_ACCESS_IN_NODE=false` is no longer needed.

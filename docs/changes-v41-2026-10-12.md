# v41 (2026-10-12): welcome points and points messages

Base v40. Nothing deployed, published, migrated on a live database, or paid for. No schema change (no new migration).

## Added and changed
- **Welcome points, once.** A verified account's starting balance (`STARTING_POINTS`, empty means 50) is credited once (unchanged one-grant rule from v37). New: the server remembers whether the welcome message has been shown (a zero-point ledger row `welcome_seen`, created by `POST /api/points/welcome`). `/api/work` now returns `points.welcome {amount, grantedAt, show}`. Sign-in, refresh, retry, profile edits and repeat sign-ups never grant points or show the message again. A zero amount or a deleted account shows no message.
- **Messages** (`components/whatslearn/points-burst.tsx`, one block of CSS marked `v41`): "Welcome! 50 points added" (with the balance), "+X points" with the new balance after a mission earns points, and "−N points for this clue" with the new balance after a clue is charged (repeat clues cost and show nothing). Clue cost still appears on each clue button before it is revealed. Guest equivalents are labelled "kept in this browser only". Brief (about 4 seconds, dismissable), polite screen-reader announcement, no sound; a few small dots rise for welcome and mission points only. With reduced motion there is no animation and no dots, and the message stays 6 seconds.
- **Guest wording.** The rewards line and help now say guests do not get the account welcome balance and that guest progress is local to this browser.
- `/api/work` returns the new balance in `award.balance` after a save.
- Docs: `docs/deployment-guide.md` section 3A (welcome points and what a real sign-up needs), `docs/handoff-v41-2026-10-12.md`.
- Existing look unchanged: the interface-fingerprint test records the one new element in the learn page.

# Changes v55 (2026-10-14)

Built on v54. v50 to v54 untouched. Backend, scoring, rules and site unchanged.

- Why: the owner cannot set the n8n server variable `NODE_FUNCTION_ALLOW_BUILTIN=crypto`. Without it every Code node that used `require("crypto")` failed, so chat, sync and reminders could not run.
- The six Code nodes that signed requests or checked Meta's signature (`wa-check-signature.js`, `wa-sign-message.js`, `notices-sign-claim.js`, `notices-sign-report.js`, `reminders-sign-claim.js`, `reminders-sign-report.js`) now carry a small pure-JavaScript HMAC-SHA256 (SHA-256, HMAC, constant-time compare, random nonce). No `require()` anywhere in `n8n/code/`.
- Same rules as before: Meta signature checked in n8n and again in the backend, signed 300 s bridge requests with nonce, dedupe by message id, LINK-only matching, STOP, scoring only in the backend.
- Nonce uses `Math.random` (it only has to be unique per request; the timestamp, signature and backend replay check carry the security).
- Why not the n8n Crypto node: not needed. The Code node route keeps the same wiring and is tested against Node's crypto.
- `n8n/workflows/whatslearn-all-in-one.json` regenerated (46 nodes, no `require`).
- `tests/whatsapp-bridge.cjs`: test harness now throws if a Code node calls `require`; new tests prove no `require` in any Code node, and that the built-in HMAC equals Node's for 140 inputs (empty, long keys over 64 bytes, non-ASCII, lone surrogate, raw bytes).
- Guide: `docs/whatsapp-n8n-setup-v55.md` (step-by-step finish, where to find appSecret, phoneNumberId and webhook in Meta, no server settings).

# v36 (12 October 2026): course order, practical tasks, sharper questions, course titles

Built from v35 in a separate working copy. Nothing was deployed or published; the original ZIP, the source project, the live Site and every database were not touched. No new migration.

## Course order (locks)
- Inside each course, mission 2 opens only after mission 1 is **completed**, mission 3 after mission 2, and so on. Courses do not depend on each other; the first mission of every course is always open.
- **Completed** means the understanding answer is correct and the practical task was accepted (the server never saves work with a wrong understanding answer, so a saved mission is a completed mission).
- Enforced on the server for signed-in learners in `lib/mission-points.ts` (`saveMissionWork`) and in `app/api/work/route.ts` (HTTP 403, "Locked. Finish “…” first"). The assistant save tool goes through the same code. Completed missions always stay open to practise.
- The mission screen shows locked missions as disabled ("Locked · finish “…” first", lock icon) on the Today map and the Skill paths list. A locked mission opened by a link or the assistant shows a short locked panel instead of the lesson, with a button to the mission to finish first.
- Guests: the same order is checked in the browser from the work saved on that device. Because that storage can be edited or cleared, the page says this order is checked on this device only and that signing in checks it on the account.
- The one-new-scored-mission-per-India-day limit (Asia/Kolkata) is unchanged. Completing mission 1 and mission 2 therefore happens on different India days.

## Wrong understanding answers
A wrong answer shows the mission's direct explanation and says, before the learner answers and after, that a wrong answer never costs points and can be retried as often as they like. Nothing is saved, no points are removed and nothing unlocks until the answer is right. The server (and the assistant tool and the guest store) return the same explanation.

## Points and clues
- Points available are stated before starting (the mission dialog: "up to 100 mission points (understanding 25 + practical 75) · each clue costs 5 points, at most 10 per mission"). Once a clue is used it reads "90 of 100 points available now (2 clues used, −10)".
- Clue buttons state their cost: "(−5 points)", then "(−5 points)", then "(no extra cost)" once the cap of 10 is reached, and "(already used)" for a clue already opened. The server records each clue once per mission; the same clue again costs nothing. After a mission is scored, more clues change nothing. The score never goes below zero.
- Clue use is stored per mission (`mission_clues`, then `mission_scores.clues`) and counted per course for titles. Using a clue never touches practice days or the streak.
- Duplicate scores are impossible: the database allows one score per mission and one per India day; refreshes, repeats, two tabs and simultaneous requests are covered by tests.

## Course titles
Finishing all 10 missions of a course earns a title. Titles are recognition inside WhatsLearn, not a qualification and not a statement about ability, IQ or job readiness.
| Course | Top title (no clue used on any of the 10, every mission scored here) | Lower title (all 10 completed, at least one clue used or a mission completed before points existed) |
|---|---|---|
| AI Digital Marketing | Campaign Strategist | Campaign Practitioner |
| AI Full-Stack Development | Full-Stack Builder | Full-Stack Practitioner |
| AI Filmmaking | Lead Filmmaker | Filmmaking Practitioner |
| AI-powered Visual Storytelling | Lead Visual Storyteller | Visual Storytelling Practitioner |
The exact rules sit in the existing "How do I collect rewards?" help (`lib/course-titles.ts`, `components/whatslearn/practice-rewards.tsx`). The titles appear as two badges in the existing collection. The streak is unchanged, and a missed day never removes points, work, completed missions or a title.

## Practical tasks and new content (all 40 missions)
- Every mission now has one scenario-based understanding question (3–4 plausible options, a direct explanation) and one practical "try it" task made of 2–5 structured parts (choice, short text, longer text, code), the existing "Your reasoning" box, and, on most missions, an optional https link. The 10 old missions whose questions were generic (all had an obvious "B") were rewritten as well.
- Marketing: offer, campaign brief, follow-up messages, research questions, A/B test plan, channel plan, measurement plan, two-week content calendar, honest ad rewrite, one-page campaign plan.
- Full-Stack: one tutor-booking project across the 10 missions: feature and acceptance checks, code review, SQL schema, endpoint contract, validation code, a bug to fix (prefilled starter), access check, tests, branch and rollback commands, launch checklist. 13 code fields. Code is stored and shown as text only. It is never run, compiled or opened.
- Filmmaking: logline and beats, six-shot list, hybrid shoot plan, dialogue, directing notes, location and light, sound cue sheet, edit decision list, call sheet and budget, one-page pitch.
- Visual Storytelling: three-frame story, AI image brief, core message, poster plan, colour and type choices, chart story, carousel outline, AI image critique, three-slide pitch, five-frame campaign storyboard.
- Content: `lib/practical/*.json` (shipped, no answers), applied in `lib/practical-content.ts`. Sample answers used only by tests are in `tests/fixtures/practical-samples/`.
- The answer is one text body (sections headed `### Label`), so drafts, saved work, the portfolio and the download work as before; the portfolio and download show it as readable "Label:" lines.
- Links: https only, no address with a login, no localhost or private addresses; stored as text and never opened or fetched by the site.
- Relevance checks read only what the learner typed (short and long parts plus the reasoning), not choices or code, so choices and code cannot be mistaken for filler or terminal logs. Own-words answers pass; nonsense, filler, copied course text and off-topic answers are refused, as before. Paste is not blocked and there is no plagiarism detection claim.
- Feedback is labelled "quick check". "AI review" only appears for a complete AI response.

## What file attachments would need (not built)
Attachments are not offered in v36; the practical tasks take text, code and an optional link. The existing storage is a D1 database with no file store, so safe attachments would need: an R2 bucket binding in `wrangler.jsonc` and the Sites host; an upload route that checks sign-in, same origin and a per-learner quota; an allow-list (PNG, JPEG, WebP, PDF; MP4 only if wanted) with a size limit (for example 5 MB images, 25 MB video), checked by file signature and not just the extension; random object names, private access with short-lived links, and no inline execution; a retention rule shown to learners (for example deleted 90 days after the last save, and on account deletion); virus scanning if video or documents are allowed; and wording that a file is stored for the learner and has not been reviewed by AI unless an AI review really read it.
